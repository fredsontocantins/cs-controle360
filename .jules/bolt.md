## 2026-05-24 - [N+1 Summary Optimization]
**Learning:** The `/api/summary` endpoint was suffering from an N+1-like performance bottleneck because it called `list_*` functions (which perform database queries and full result set processing) multiple times within a loop for each reporting cycle. Pre-fetching all entities once and filtering them in-memory reduced execution time significantly. Additionally, `datetime.fromisoformat` is drastically faster than `strptime` for ISO strings, and combining it with `@lru_cache` on parsing helpers provides a measurable boost when processing large record sets.
**Action:** Always pre-fetch full record sets when generating summaries that involve multiple time windows or cycles. Use `fromisoformat` and `lru_cache` for repeated datetime parsing operations.
